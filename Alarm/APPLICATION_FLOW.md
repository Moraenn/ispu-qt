# Работа приложения "Будильник"

## Назначение файла
Этот файл поясняет, как работает приложение на уровне потока выполнения: что запускается первым, какие объекты создаются, какие сигналы передаются, какие слоты вызываются и зачем это нужно.

## 1. Общая логика приложения
Приложение построено как обычное Qt Widgets-приложение.

Основные участники:

1. `QApplication`
   Отвечает за запуск графического приложения, обработку событий и цикл выполнения программы.
2. `AlarmWindow`
   Главное окно приложения. В нем создаются все виджеты интерфейса и реализуется логика будильника.
3. `QTimer`
   Генерирует сигнал каждую секунду, чтобы приложение могло обновлять текущее время.
4. `QLCDNumber`
   Отображает текущее время.
5. `QSpinBox`
   Позволяют задать часы и минуты срабатывания будильника.
6. `QCheckBox`
   Включает и выключает будильник.
7. `QLabel`
   Показывают установленное время и текущий статус будильника.

## 2. Поток выполнения после запуска

### Шаг 1. Вход в `main.cpp`
После запуска программы управление попадает в `main.cpp`.

Что происходит:

1. Создается объект `QApplication`.
2. Создается объект `AlarmWindow`.
3. Вызывается `show()`, чтобы отобразить окно.
4. Запускается `app.exec()`.

Зачем это нужно:

- `QApplication` запускает цикл событий Qt.
- Пока работает цикл событий, приложение реагирует на действия пользователя и сигналы таймера.

## 3. Что происходит в конструкторе `AlarmWindow`
Когда создается объект `AlarmWindow`, выполняется конструктор класса.

В конструкторе последовательно происходят следующие действия:

1. `setupUi()`
   Создаются все виджеты интерфейса и размещаются с помощью компоновок.
2. `connectSignals()`
   Настраиваются сигнально-слотовые соединения между элементами интерфейса и логикой окна.
3. `updateAlarmPreview()`
   Сразу обновляется текст с установленным временем и текущим состоянием будильника.
4. `updateCurrentTime()`
   На экран выводится текущее системное время.
5. `m_clockTimer->start(1000)`
   Запускается таймер с интервалом 1000 мс, то есть 1 секунда.

Зачем это нужно:

- Окно должно сразу отображать корректные данные.
- Таймер нужен, чтобы интерфейс автоматически обновлялся без участия пользователя.

## 4. Как создается интерфейс в `setupUi()`
Метод `setupUi()` отвечает только за создание и настройку визуальных элементов.

Что именно он делает:

1. Задает параметры окна: заголовок и размер.
2. Создает `QLCDNumber` для отображения текущего времени.
3. Создает группу настройки будильника.
4. Создает два `QSpinBox`:
   - один для часов от `0` до `23`
   - один для минут от `0` до `59`
5. Создает `QCheckBox` для включения будильника.
6. Создает текстовые метки со статусом и установленным временем.
7. Размещает элементы в `QHBoxLayout` и `QVBoxLayout`.
8. Устанавливает начальное время будильника на текущее системное время плюс 1 минута.

Зачем это нужно:

- Все элементы должны быть созданы до того, как приложение начнет с ними работать.
- Компоновки автоматически управляют расположением элементов и подстраивают интерфейс.

## 5. Как работают сигналы и слоты в `connectSignals()`
Метод `connectSignals()` связывает события интерфейса с методами обработки.

Используются следующие соединения:

1. `QTimer::timeout()` -> `updateCurrentTime()`
   Каждую секунду вызывается обновление текущего времени.
2. `QSpinBox::valueChanged(int)` -> `updateAlarmPreview()`
   При изменении часов или минут обновляется текст с установленным временем.
3. `QCheckBox::toggled(bool)` -> `setAlarmEnabled(bool)`
   При включении или выключении будильника обновляется статус.

Зачем это нужно:

- Интерфейс становится реактивным.
- Не нужно постоянно вручную проверять состояние всех элементов.
- Qt сам вызывает нужный слот, когда происходит соответствующее событие.

## 6. Что происходит каждую секунду
После запуска таймера каждую секунду генерируется сигнал `timeout()`.
Этот сигнал вызывает слот `updateCurrentTime()`.

Внутри `updateCurrentTime()` происходит следующее:

1. Считывается системное время через `QTime::currentTime()`.
2. В `QLCDNumber` выводится строка формата `hh:mm:ss`.
3. Проверяется, включен ли будильник.
4. Если будильник выключен, метод завершает работу.
5. Если будильник включен, сравниваются:
   - текущий час
   - текущая минута
   - час будильника
   - минута будильника
6. Если время совпало, дополнительно проверяется, не срабатывал ли будильник уже в эту же минуту.
7. Если это новое срабатывание, вызывается `triggerAlarm()`.

Зачем нужна дополнительная проверка:

- Таймер срабатывает каждую секунду.
- В течение одной и той же минуты условие совпадения времени истинно много раз.
- Без защиты сообщение о будильнике открылось бы несколько раз.

## 7. Что происходит при изменении времени будильника
Когда пользователь меняет значение хотя бы одного `QSpinBox`, автоматически вызывается `updateAlarmPreview()`.

Этот метод:

1. Формирует строку времени в формате `часы:минуты`.
2. Обновляет метку `Установленное время`.
3. Проверяет, включен ли будильник.
4. Обновляет текст статуса:
   - если включен, пишет, что будильник ожидает сигнала
   - если выключен, пишет, что будильник выключен
5. Вызывает `resetTriggeredState()`

Зачем вызывается `resetTriggeredState()`:

- Если пользователь изменил время будильника, старое состояние срабатывания больше неактуально.
- Приложение должно считать новую настройку новым событием.

## 8. Что происходит при включении и выключении будильника
Когда пользователь нажимает на `QCheckBox`, Qt передает сигнал `toggled(bool)` в слот `setAlarmEnabled(bool)`.

Внутри `setAlarmEnabled(bool)`:

1. Проверяется значение `enabled`.
2. Если `true`, статус меняется на "Будильник включен. Ожидание сигнала."
3. Если `false`, статус меняется на "Будильник выключен."
4. После этого вызывается `resetTriggeredState()`.

Зачем это нужно:

- Интерфейс должен сразу отражать текущее состояние.
- При повторном включении будильник должен заново быть готов к срабатыванию.

## 9. Что происходит при срабатывании будильника
Если текущее время совпало с установленным и это еще не было обработано в текущую минуту, вызывается `triggerAlarm()`.

Метод `triggerAlarm()` делает следующее:

1. Сохраняет текущую дату, час и минуту в поля:
   - `m_lastTriggeredDate`
   - `m_lastTriggeredHour`
   - `m_lastTriggeredMinute`
2. Меняет текст статуса на тревожное сообщение.
3. Меняет цвет текста статуса, чтобы срабатывание было заметно визуально.
4. Вызывает `QApplication::beep()`.
5. Показывает `QMessageBox::information(...)` с сообщением для пользователя.

Зачем сохраняется последнее срабатывание:

- Это защита от повторного вызова сигнала в ту же минуту.
- Без этого каждый следующий тик таймера снова вызывал бы окно сообщения.

## 10. Назначение `resetTriggeredState()`
Этот метод сбрасывает информацию о последнем срабатывании.

Он устанавливает:

- пустую дату
- `-1` для часа
- `-1` для минуты

Зачем это нужно:

- После смены времени будильника или изменения состояния флажка приложение должно забыть предыдущий факт срабатывания.
- Иначе новая настройка могла бы ошибочно считаться уже обработанной.

## 11. Смысл потока данных в приложении
Если упростить, поток работы можно описать так:

1. Приложение запускается.
2. Создается окно и все элементы интерфейса.
3. Таймер начинает каждую секунду передавать сигнал `timeout()`.
4. Слот `updateCurrentTime()` обновляет часы на экране.
5. Пользователь задает время через `QSpinBox`.
6. Пользователь включает будильник через `QCheckBox`.
7. Когда текущее время совпадает с установленным, вызывается `triggerAlarm()`.
8. Пользователь получает визуальное и звуковое уведомление.

## 12. Краткая схема вызовов

```text
main.cpp
  -> QApplication
  -> AlarmWindow
      -> setupUi()
      -> connectSignals()
      -> updateAlarmPreview()
      -> updateCurrentTime()
      -> QTimer::start(1000)

QTimer::timeout()
  -> updateCurrentTime()
      -> display current time
      -> compare current time with alarm time
      -> triggerAlarm() при совпадении

QSpinBox::valueChanged(int)
  -> updateAlarmPreview()
      -> update labels
      -> resetTriggeredState()

QCheckBox::toggled(bool)
  -> setAlarmEnabled(bool)
      -> update status
      -> resetTriggeredState()
```

## 13. Итог
Приложение работает по событийной модели Qt.
Это означает, что программа не выполняет постоянный ручной опрос всех элементов интерфейса, а ждет события:

- тик таймера
- изменение значения
- нажатие флажка

После наступления события Qt автоматически передает управление нужному слоту. За счет этого код получается логически разделенным:

- создание интерфейса
- настройка связей
- обновление времени
- обработка состояния будильника
- реакция на срабатывание

Именно в этом и состоит основная идея сигнально-слотового механизма в данном приложении.
