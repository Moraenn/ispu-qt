## Что находится в комплекте

| Работа | Папка | Содержание |
|---|---|---|
| 1 | `Calculator` | Калькулятор, сигналы/слоты, обработка клавиатуры и ошибок |
| 2 | `Alarm` | Будильник: текущее время, настройка и однократный сигнал в заданную минуту |
| 3 | `handbook_lab3` | Справочник марок, собственные модель, представление, делегат и диалог |
| 4 | `handbook` | Развитие справочника: бинарная сериализация, открытие/сохранение, защита несохранённых изменений |
| 5 | `StudyPlanner` | Планировщик заданий, журнал занятий, фильтры, статистика, JSON, резервные копии и CSV |

`handbook_lab3` — отдельный этап без файловых операций. ЛР4 не подменяет ЛР3: она использует те же классы и добавляет хранение. `AlarmWindow`, `qt-console1`, `test1`, старые сборки и служебные файлы IDE в комплект не переносились. Это подготовленная рабочая копия, а не полный клон истории репозитория.

## Сборка всех приложений

Нужны компилятор C++17, CMake 3.16 или новее и комплект разработки Qt с модулями Widgets и Test. Исходники ориентированы на API Qt 5.15 / Qt 6; проверены Qt 6.4.2 и 6.9.2, а Qt 5.15 отдельно не проверялась. Версии компилятора и Qt должны быть совместимыми: не смешивать MinGW и MSVC.

Проще открыть **корневой `CMakeLists.txt`** в Qt Creator, выбрать установленный Desktop Kit, настроить и собрать проект. Затем выбрать нужную цель запуска: `Calculator`, `Alarm`, `handbook_lab3`, `handbook` или `StudyPlanner`.

Командная строка из среды установленного Qt:

```sh
cmake -S . -B build -DBUILD_GUI=ON -DBUILD_TESTING=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Если CMake не находит Qt, задайте `CMAKE_PREFIX_PATH` на каталог своего комплекта. Пример формы команды для Windows (путь нужно заменить на существующий):

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/<version>/<kit>" -DBUILD_TESTING=ON
```

Для запуска вне Qt Creator каталог `bin` своего Qt должен быть в `PATH`; при переносе программ на другой компьютер требуется отдельное развёртывание зависимостей Qt. Готовые `.exe` и зависимости находятся в `dist/windows`.

Каждая папка также содержит отдельный `CMakeLists.txt` и `.pro` для qmake. Сохраняйте общую структуру папок: `main.cpp` использует `../common/capture.h`. Обычное приложение от функции снимков не зависит по поведению; снимок выполняется только с параметром `--screenshot`.

## Проверка ядра без Qt

```sh
cmake -S . -B build-core -DBUILD_GUI=OFF -DBUILD_TESTING=ON
cmake --build build-core --config Release --parallel
ctest --test-dir build-core -C Release --output-on-failure
```

Подробный протокол печатает `domain_tests` из `build-core/bin` (либо `bin/Release` при многоконфигурационной сборке).

## Данные и демонстрация

ЛР3 не сохраняет коллекцию при закрытии — это отдельный этап работы. В ЛР4 сохранение выполняется командами «Сохранить» и «Сохранить как», используется расширение `.stamps`. Пример `examples/collection.stamps` сформирован по описанному формату; сохранение и открытие коллекций проверены через Qt Test. Демонстрационные марки не являются достоверным историческим каталогом.

Планировщик обычно хранит `study-plan.json` в каталоге `QStandardPaths::AppDataLocation`. Точный путь показан в строке состояния. Его можно задать самостоятельно:

```sh
StudyPlanner --data "my-data/study-plan.json"
```

При отсутствии файла создаётся пустой план. При повреждении существующего файла программа сообщает об ошибке, а не заменяет его пустыми данными. Для отдельной демонстрации без изменения рабочего файла:

```sh
StudyPlanner --demo
StudyPlanner --demo --tab 2
```

Демонстрация создаёт четыре задания и два занятия во временной папке. Даты привязаны к текущему дню. План: 330 минут; факт: 105; выполнено: 1 из 4 (25%); просрочено: 1. После закрытия демонстрационные изменения удаляются. `--demo` имеет приоритет над `--data`.

В `examples/study-plan.json` — фиксированный пример с датами октября 2026 года. Его можно восстановить через меню «Файл»; просроченность при этом зависит от даты запуска.

## Реальные скриншоты и обновление отчётов

После сборки в каждой целевой ОС выполните:

```sh
python tools/capture_all.py --build build --label windows
```

В Ubuntu используйте `--label ubuntu`. Скрипт проверяет соответствие метки текущей ОС, запускает именно собранные приложения и сохраняет снимки в `reports/screenshots/<os>/`. Для Linux нужна действующая графическая сессия. Параметр `--label linux` не является подтверждением запуска в Ubuntu.

Скрипт снимает основные окна и три вкладки планировщика. Ещё пять снимков каждой ОС получены из Qt Test при заданной переменной `ISPU_SCREENSHOT_DIR`. Для диалогов Windows использован параметр `-style Fusion`.

Проверку Ubuntu можно повторить, собрав образ по `tools/Dockerfile.ubuntu` и запустив `tools/verify_ubuntu.sh` в контейнере с исходниками, подключёнными к `/work`.

Для сборки установленным MSYS2 используйте путь с латинскими буквами, например `C:/work/ispu-qt`: его инструмент `moc` не смог создать файлы в пути с кириллицей.

Редактируемые отчёты расположены в `reports/docx/`. Общий отчёт содержит все пять работ; отдельные — каждую работу. Диаграммы включены и в виде PNG, и в исходном формате Graphviz DOT.

Для повторной сборки отчётов после добавления снимков нужны Python, `python-docx` и Pillow:

```sh
python -m pip install python-docx Pillow
python tools/build_reports.py --student "Исмайлов В.П." --group "4-41"
```

На титульных листах указана текущая группа 4-41. Примеры на диске относятся к прошлому семестру и имеют группу 3-41; при необходимости семестрового обозначения запустите генератор с `--group "3-41"`. Год — 2026. Подтверждённые результаты дополнительных тестов внесите в `reports/content.json` и обновите статус в `reports/verification.json`; сам генератор не объявляет проверки пройденными только по наличию картинки.

## Как перенести изменения в свой репозиторий

Сначала сделайте копию своей рабочей папки или отдельную ветку. Из этого комплекта добавьте `StudyPlanner`, `handbook_lab3`, `common`, `tests`, `tools`, `examples`, корневой `CMakeLists.txt`; обновите `Calculator`, `Alarm`, `handbook` после просмотра различий. Не удаляйте прежние материалы и не переносите чужие сборочные каталоги.

Подробности: `CHANGES.md`, `DEFENSE.md`, `REPORT_STYLE.md`. `verification/STATUS.md` отделяет выполненные проверки от подготовленных. Чужие отчёты в архив не включены.
