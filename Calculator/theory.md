# Теория по проекту `Calculator` на Qt

Этот текст написан так, будто я объясняю проект человеку, который уже знает C++, но ещё не знаком с Qt.

## 1. Что такое Qt

Qt — это библиотека для создания графических приложений.

Если говорить очень просто:

- стандартный C++ даёт нам язык;
- Qt даёт готовые инструменты для окон, кнопок, текстовых полей, событий, таймеров, сигналов и слотов;
- благодаря Qt можно писать одно приложение и запускать его на разных системах.

В этом проекте Qt нужен для создания обычного оконного калькулятора.

## 2. Из каких файлов состоит проект

В проекте есть несколько главных файлов.

### `Calculator.pro`

Это файл проекта для `qmake`.

Он говорит Qt, какие исходники и заголовки нужно собирать. Проще говоря, это инструкция для сборки проекта.

### `main.cpp`

Это точка входа в программу.

Именно здесь создаётся объект `QApplication`, потом создаётся окно калькулятора, а затем запускается цикл обработки событий.

### `calculator.h`

Это описание класса `Calculator`.

Здесь мы объявляем:

- от какого класса наследуемся;
- какие поля хранит калькулятор;
- какие методы у него есть;
- какие слоты он умеет обрабатывать.

### `calculator.cpp`

Это реализация класса `Calculator`.

Здесь создаётся интерфейс, настраиваются кнопки, обрабатывается ввод и выполняются вычисления.

## 3. Зачем нужен `QApplication`

В консольной программе `main()` часто просто вызывает функции и заканчивается.

В графическом приложении всё иначе. Программа должна постоянно ждать события:

- нажатие кнопки мыши;
- нажатие клавиши;
- перемещение окна;
- перерисовку интерфейса.

Именно для этого нужен `QApplication`.

Он запускает цикл событий:

```cpp
return a.exec();
```

Пока этот цикл работает, окно живёт и реагирует на действия пользователя.

## 4. Почему `Calculator` наследуется от `QWidget`

`QWidget` — это базовый класс для обычных визуальных элементов интерфейса в Qt.

Когда мы пишем:

```cpp
class Calculator : public QWidget
```

мы говорим: "наш калькулятор — это собственный виджет, то есть собственное окно/элемент интерфейса".

Это удобно, потому что наш класс сразу получает готовые возможности Qt:

- может отображаться на экране;
- может получать события клавиатуры;
- может содержать кнопки и метки;
- может использовать layout для расположения элементов.

## 5. Что делает `Q_OBJECT`

Макрос `Q_OBJECT` нужен для механизма сигналов и слотов Qt.

Без него многие возможности Qt для пользовательских классов не будут работать правильно.

Для новичка можно запомнить так:

- если класс наследуется от `QObject` или `QWidget`;
- если в нём есть слоты, сигналы или другая метаинформация Qt;
- значит, почти всегда нужен `Q_OBJECT`.

## 6. Что такое сигналы и слоты

Это одна из самых известных идей Qt.

Простая модель такая:

- сигнал говорит: "что-то случилось";
- слот говорит: "вот что нужно сделать в ответ".

Например, у кнопки есть сигнал `clicked`.

Мы соединяем его со слотом калькулятора:

```cpp
connect(button, &QPushButton::clicked, this, &Calculator::slotButtonClicked);
```

Смысл строки такой:

"Когда пользователь нажмёт эту кнопку, вызови у текущего калькулятора метод `slotButtonClicked()`."

Это очень удобно, потому что интерфейс сам сообщает программе о событиях.

## 7. Какие виджеты используются в калькуляторе

В проекте используются самые базовые элементы.

### `QLabel`

Это текстовая надпись.

В калькуляторе их две:

- верхняя показывает выражение;
- нижняя показывает текущее число или результат.

### `QPushButton`

Это обычная кнопка.

Каждая кнопка содержит символ:

- цифру;
- точку;
- оператор;
- `=`;
- `CE`.

### `QGridLayout`

Это менеджер размещения элементов в виде таблицы.

Он нужен, чтобы не выставлять координаты вручную.

Вместо этого мы говорим:

- этот элемент положить в строку 0, столбец 0;
- этот элемент положить в строку 3, столбец 2;
- и так далее.

Так интерфейс получается чище и логичнее.

## 8. Как создаётся интерфейс

В конструкторе `Calculator` происходит главная сборка окна.

Шаги такие:

1. Создаются две метки `QLabel`.
2. Создаётся таблица символов кнопок.
3. Создаётся `QGridLayout`.
4. Метки и кнопки добавляются в layout.
5. Layout назначается всему окну через `setLayout(...)`.

То есть интерфейс собирается прямо в коде.

## 9. Зачем здесь стек `QStack<QString>`

В этом проекте стек хранит промежуточное состояние вычисления.

Идея очень простая:

- сначала пользователь вводит первое число;
- потом оператор;
- потом второе число;
- потом выполняется вычисление.

В стек кладутся строки:

- первое число;
- оператор;
- второе число.

После этого метод `calculate()` достаёт их и считает результат.

Для учебного проекта это хороший вариант, потому что он простой и легко объясняется.

## 10. Как работает ввод

Главный метод для обработки ввода — `input(const QString &text)`.

Он получает один символ или команду:

- цифру;
- точку;
- оператор;
- знак `=`.

Дальше метод решает, что делать:

- если пришла цифра, добавить её к текущему числу;
- если пришёл оператор, запомнить первое число и знак операции;
- если пришёл `=`, завершить вычисление;
- если был показан текст `Ошибка`, сначала очистить состояние.

Это очень важная идея: и кнопки мыши, и клавиатура используют одну и ту же логику `input(...)`.

Так код проще поддерживать, потому что вычисления описаны в одном месте, а не в двух разных.

## 11. Как работает `calculate()`

Метод `calculate()` делает четыре шага:

1. Берёт из стека второе число.
2. Берёт из стека оператор.
3. Берёт из стека первое число.
4. Выполняет нужное действие.

Если оператор:

- `+`, то числа складываются;
- `-`, то второе вычитается из первого;
- `*`, то числа умножаются;
- `/`, то первое делится на второе.

Отдельно обработано деление на ноль. В этом случае вместо странного результата пользователь видит слово `Ошибка`.

## 12. Как работает клавиатура

Qt посылает события клавиатуры через метод `keyPressEvent(QKeyEvent *event)`.

В нашем проекте он обрабатывает:

- цифры;
- `+`, `-`, `*`, `/`;
- `Enter` и `Return` как `=`;
- `Backspace`, `Delete`, `Escape` как очистку;
- `,` как десятичную точку.

Очень важно понимать: чтобы окно действительно ловило клавиши, у него должен быть фокус.

Именно поэтому:

- у калькулятора включён `Qt::StrongFocus`;
- у кнопок выключен фокус через `Qt::NoFocus`.

## 13. Чем хорош layout по сравнению с ручными координатами

Новички часто хотят ставить кнопки по координатам вроде `(x, y)`.

Так можно, но это быстро становится неудобно.

`QGridLayout` лучше, потому что:

- код короче;
- интерфейс легче менять;
- расположение элементов логичнее;
- меньше шанс ошибиться в позиционировании.

Для калькулятора layout — почти идеальный выбор.

## 14. Как объяснить проект преподавателю

Вот простой и уверенный способ рассказать о проекте.

### Короткая суть

"Я сделал оконный калькулятор на Qt. Основной класс `Calculator` наследуется от `QWidget`, внутри него создаются метки и кнопки, а их расположением управляет `QGridLayout`. Нажатия кнопок подключены через сигналы и слоты, а клавиатура обрабатывается через `keyPressEvent`. Для промежуточного состояния вычислений используется `QStack<QString>`."

### Что особенно важно подчеркнуть

- Qt даёт не только виджеты, но и модель событий.
- Один и тот же метод `input(...)` обрабатывает и кнопки, и клавиатуру.
- Интерфейс отделён от вычисления хотя бы на базовом уровне: отдельный ввод, отдельный расчёт.
- Приложение использует цикл событий `QApplication`.

### Если спросят, почему выбран именно такой подход

Можно ответить так:

"Я сознательно оставил проект простым и учебным. Здесь нет сложного парсера выражений и приоритетов операций, потому что цель проекта — показать базовую работу с Qt: виджеты, layout, события, сигналы и слоты, обработку клавиатуры и простую бизнес-логику."

## 15. Как мысленно сравнивать Qt и обычный C++

Полезная аналогия такая:

- обычный C++ — это язык и базовые инструменты;
- Qt — это большой набор готовых деталей для GUI-приложений;
- `QWidget` — заготовка для визуального компонента;
- `connect(...)` — связь между событием и реакцией;
- `QApplication` — диспетчер жизни всего приложения.

## 16. Что стоит запомнить из этого проекта

Если нужно унести из проекта только самое важное, то вот оно:

1. В Qt почти всё крутится вокруг событий.
2. Виджеты строят интерфейс.
3. Layout управляет расположением элементов.
4. Сигналы и слоты связывают действия пользователя с логикой программы.
5. `keyPressEvent(...)` позволяет обрабатывать клавиатуру.
6. Даже простой GUI-проект лучше делать аккуратно: понятные имена, проверка ошибок, единая логика ввода.
